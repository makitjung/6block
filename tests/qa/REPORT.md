## 2. 수정한 결함 5건

### M-1 (Medium) 연도 극단값에서 하루·주간 화면이 500 → 수정

원인은 두 곳이었다. `app/routes/day.py:180` 의 다음날 계산(`d + 1일`)과
`app/common.py:340` `week_lt_items` 의 그 주 일요일 계산(`월요일 + 6일`)이 각각
10000년을 만들어 `OverflowError` 를 그대로 올려보냈다. 형식 검사는 통과한 뒤 계산에서
터지므로 입력 검증이 잡지 못했다.

실측한 정확한 경계다.

| 날짜 | 다음날 계산 | 그 주 일요일 | 수정 전 |
|---|---|---|---|
| 9999-12-26 (일) | OK | OK | 200 |
| 9999-12-27 (월) ~ 12-30 | OK | 터짐 | 500 |
| 9999-12-31 (금) | 터짐 | 터짐 | 500 |

**고친 방법.** 계산부 세 곳에 `try/except` 를 각각 다는 대신 입구 하나를 좁혔다.
`app/common.py` 에 `MAX_YEAR = 9000` 을 두고 `_parse_date` 가 그 위를 `None` 으로 거른다.
이 함수가 `/day`·`/week`·`/save/day`·`/save/field`·`/api/day`·장기 항목 날짜의 공통 관문이라
한 번의 수정으로 전부 닫힌다. CLAUDE.md 6절("50줄로 되면 200줄로 쓰지 않는다")에 맞는 선택이다.

**실제 구동 서버(uvicorn, 포트 8024)에서 확인한 결과다.**

| 요청 | 수정 전 | 수정 후 |
|---|---|---|
| `GET /day/9999-12-31` | 500 | **307** (오늘로 보냄) |
| `GET /day/9999-12-30` | 500 | **307** |
| `GET /day/9999-12-27` | 500 | **307** |
| `GET /week/9999-12-31` | 500 | **307** |
| `GET /api/day/9999-12-31` | 500 | **400** (명확한 오류) |
| `GET /day/2026-08-16` | 200 | **200** (영향 없음) |

### M-2 (Medium) 종일 이벤트 다음날 계산에 가드가 없었다 → 수정

`gcal_write._next_day` 가 `OverflowError` 를 던져 고결감 저장 전체를 500 으로 만들 수 있었다.
날짜가 담긴 `ValueError` 로 바꿔, 부르는 쪽의 기존 `except` 가 '캘린더 반영 실패'로 처리하고
기록 자체는 저장되게 했다. 함께 `reflect_add`·`reflect_update` 의 `review_date` 를
`_parse_date` 로 검증하게 했다(예전에는 검증 없이 DB 와 캘린더로 흘렀다).

실제 서버 확인이다. `POST /reflect/add` 에 `review_date=9999-12-31` 을 넣으면
`{"ok":true,"id":1,"synced":false}` 로 기록은 저장되고 못 쓰는 날짜만 버려진다.

### M-3 (Medium) /plan 이 항목 수에 초선형으로 느려졌다 → 수정

병목은 `app/routes/plan.py:204` `_assign_lanes` 였다. 칸을 물어볼 때마다 잡힌 구간 목록
전체를 훑었고(`any(lo <= i < hi for lo, hi in held)`), 영역이 바뀔 때마다 막대 전체를 다시
순회해 최대 칸을 구했다(`max(b["lane"] for b in bars ...)`).

**고친 방법.** 잡힌 구간 목록을 잡힌 칸 번호 집합으로 바꿔 O(1) 조회로, 최대 칸은 `put` 에서
갱신하는 `max_lane` 추적으로 바꿨다. 알고리즘의 계층·영역·기간 규칙은 한 줄도 건드리지 않았다.

**결과가 한 칸도 달라지면 안 되는 최적화이므로, 옛 구현을 테스트 파일에 그대로 보관해
무작위 입력 200회와 경계 5가지로 대조했다**(`tests/qa/test_p7_assign_lanes_equiv.py`).
칸 배정과 반환값이 전부 일치했다.

| 막대 수 | 옛 구현 | 새 구현 | 배율 |
|---|---|---|---|
| 200개 | 1.0ms | 0.7ms | 1.5배 |
| 800개 | 12.1ms | 3.3ms | 3.7배 |
| 2,000개 | 122.9ms | **11.7ms** | **10.5배** |

### L-1 (Low) parse_summary 가 docstring 약속을 어겼다 → 수정

`"[고민 [부제]] 제목"` 에서 비탐욕적 `(.+?)` 가 첫 `]` 에서 끊겨 `"] 제목"` 만 남겼다.
docstring 은 "형식이 아니면 (고민, **통째 제목**)" 을 약속한다.

**고친 방법.** 정규식을 `^\s*\[([^\[\]]+)\]\s*(.*)$` 로 바꿔 종류 자리에 대괄호를 허용하지
않는다. 중첩 입력은 아예 매칭되지 않고 통째 제목으로 떨어진다.

탐욕적 `(.+)` 로 바꾸는 방법은 쓰지 않았다. 그러면 `"[결정] [중요] 회의"` 가
`("결정] [중요", "회의")` 로 깨진다. 기존 동작 8가지를 표로 못 박아 회귀를 막았다.

### L-2 (Low) /save/field 가 그룹 키 없이 오면 200 을 주면서 값을 버렸다 → 수정

`_merge3` 가 `dplan1`·`dplan2`·`dplan3` 키를 찾는데 최소 폼에는 `field` 와 `value` 만 있었다.
그룹 키가 하나도 없을 때만 그 칸을 폼에 채워 넣게 했다.

**중요한 정정이 여기 붙는다.** 3단계 통합 페르소나와 적대적 검증자가 이것을
"사용자가 저장했다고 믿지만 DB 에 안 들어간다"는 **High 데이터 유실**로 판정했는데,
**둘 다 틀렸다.** 둘 다 파이썬 코드만 읽고 실제 클라이언트를 확인하지 않았다.

실제 브라우저가 보낸 요청 body 를 가로채 확인한 결과다.

```
entity=meta&id=2026-08-16&field=dplan1&value=브라우저에서 친 달성&dplan1=브라우저에서 친 달성&dplan2=&dplan3=
```

`app/static/app.js:3241-3245` 의 `bindAutoSave` 가 `data-as-prefix` 로 그룹의 세 칸을 모두
모아 보낸다(app.js:719-733 이 goal·dplan·grat·concept 각 칸에 `asPrefix`/`asIdx` 를 심는다).
타이핑한 값이 새로고침 후에도 그대로 남는 것까지 확인했다. **실사용 데이터 유실은 없었다.**
이 수정은 Record 앱·스크립트 같은 다른 클라이언트를 위한 계약 보강이다. 심각도 Low 가 맞다.

## 3. 기각한 오보 4건

거짓 양성을 남겨 두면 다음 사람이 같은 것을 다시 판다. 근거와 함께 못 박아 둔다.

### R-1 hhmm_to_min 이 형식 오류를 조용히 통과시킨다 (보고 High → 기각)

`hhmm_to_min("0800")` 이 480 을 돌려주는 것은 사실이나, 사용자 입력이 닿는 유일한 경로인
`POST /settings/blocktimes` 가 앞에서 `_valid_hhmm` 의 `^\d{2}:\d{2}$` 로 막는다(settings.py:319).
나머지 입력원 `DAY_BLOCKS` 는 코드 내장 상수다.

### R-2 slots_for_day 가 블록 경계를 넘는 슬롯을 만든다 (보고 Medium → 기각)

사실이나 `POST /settings/blocktimes` 가 `(끝-시작) % 30 != 0` 이면 400 으로 거절한다
(settings.py:332). 30분 배수가 아닌 블록은 저장될 수 없다.

### R-3 /save/field 메타 3칸 데이터 유실 (보고 High → Low 로 강등)

위 L-2 참조. 실제 브라우저 네트워크 기록으로 반증했다.

### R-4 _ai_insights 가 AI 실패 시 규칙기반 폴백을 안 한다 (보고 High → 기각)

미검증 범위 검증에서 나왔고 적대적 검증자도 확정으로 올렸으나, 근거에 사실관계 오류가 있다.
검증자는 "AI 연동이 비활성 시 사용자는 아무 개선 제안도 받을 수 없음" 이라고 적었는데
**사실이 아니다.**

- `_ai_insights` 의 docstring 은 "실패·미설정 시 **None**" 이다. None 반환이 명시된 계약이다.
- `app/routes/analytics.py:308` 이 `_build_insights`(규칙기반)를 **무조건** 계산해
  `/analytics` 화면에 늘 싣는다. AI 와 무관하다.
- AI 는 누를 때만 부르는 별도 버튼(`POST /analytics/ai`)이고, 실패하면 이유를 알려 준다.

실제 서버로 확인했다. AI 를 끈 상태에서 `GET /analytics` 는 "개선점" 절과 규칙기반 문장을
그대로 보여 주고, `POST /analytics/ai` 는
`{"ok":false,"error":".env의 AI_API_KEY와 주소·모델을 확인하세요"}` 를 돌려준다.

**여기에 폴백을 넣는 것은 오히려 잘못이다.** 사용자가 'AI 제안 받기'를 눌렀는데 규칙기반
문장을 AI 답인 것처럼 돌려주는 셈이 되고, 그 문장은 이미 같은 화면에 떠 있다.
그래서 고치지 않았다. 대신 이 판단을 테스트로 못 박았다
(`test_u_thingsai.py::test_analytics_page_always_shows_rule_based_insights`).

다만 검증자가 지적한 것 중 맞는 부분이 하나 있다. `app/integrations/ai.py:53` 주석이
"부르는 쪽(주간 자동세분화·**분석 요약**)은 None 을 받으면 규칙기반으로 넘어간다"고
적어 두었는데, 분석 쪽은 함수 단위가 아니라 화면 단위로 그렇게 동작한다. 주석 문구가
오해를 부를 수 있다. 코드 문제는 아니라 손대지 않았고, 판단은 남겨 둔다.

## 4. 1차에서 못 봤던 범위 — 이번에 검증한 결과

6개 범위, 94개 함수를 실제 실행으로 확인했다. **추가 결함 0건**이다(R-4 오보 1건 제외).

| 범위 | 테스트 | 결과 | 발견 |
|---|---|---|---|
| 구글 캘린더 쓰기 9개 함수 (가짜 서비스 객체) | 60개 | 전부 통과 | 0건 |
| 구글 캘린더 수신·캐시 (가짜 .ics) | 16개 | 전부 통과 | 0건 |
| Things3 · AI 연동 (subprocess·HTTP 가짜) | 59개 | 전부 통과 | 0건 (R-4 는 오보) |
| 동시성 · 재시작 · 마이그레이션 경쟁 | 7개 | 전부 통과 | 0건 |
| 무거운 DB 도우미 경계값 | 20개 | 전부 통과 | 0건 |
| 순환 참조 · 무한루프 | 8개 | 전부 통과 | 0건 |

특히 확인된 것을 적어 둔다.

**순환 참조는 안전하다.** 별도 프로세스에 타임아웃을 걸어 확실히 판정했다. `lt_tree_order`
가 자기참조·상호순환·3개 이상 사슬 어디에서도 무한루프에 빠지지 않는다. `_lt_root` 의
`seen` 집합 보호도 실제로 듣는다. HTTP 로도 순환을 만들 수 없다.
`POST /plan/item/reparent` 가 자기 자신·하위·손주 지정을 전부 400 으로 거절하고,
A→B 이동 후 B→A 를 시도하면 두 번째가 거절돼 순환이 생기지 않는다.

**동시성도 안전하다.** 여러 스레드가 `init_db` 를 동시에 불러도 fcntl 파일락이 직렬화해
카테고리가 중복 시드되지 않는다. `user_version=0` 으로 되돌린 DB 에서 마이그레이션을
동시에 돌려도 ALTER/DROP 이 멱등하다. 읽기와 쓰기를 겹쳐도 `database is locked` 가 나지
않는다(WAL + `busy_timeout=5000` 이 듣는다). `set_setting` 후 `get_settings` 가 즉시 새 값을
준다(stale 캐시 창 없음).

**시크릿이 새지 않는다.** `ai.status()` 가 키 값을 노출하지 않고 존재 여부만 준다.
`add_todo` 는 제목에 따옴표·개행·한글이 있어도 `subprocess.run` 인자로 안전하게 전달한다
(AppleScript 주입이 되지 않는다).

**메모리에 기록된 이중기동 레이스는 재현되지 않았다.** 다만 이는 스레드 수준 검증이고,
`multiprocessing` 으로 진짜 프로세스를 겹쳐 띄우는 것은 자식 프로세스의 conftest 격리 문제로
하지 못했다(아래 5절 참조). 즉 그 함정이 없다고 단정할 수 없다.

## 5. 프런트엔드 — 실제 브라우저로 확인한 결과

1차 보고서에서 "4개 페르소나 범위 밖"으로 남겼던 `app.js` 4,230줄을 격리 서버
(`tests/serve_isolated.py`, 포트 8024, 임시 DB)로 직접 확인했다. **운영 서버(8000)와 실제
데이터는 건드리지 않았다.**

### 확인되어 정상인 것

**자동저장 3칸 묶음.** 위 L-2 의 네트워크 기록이 근거다. 실사용 유실 없음.

**마크다운 목록 이어쓰기(CLAUDE.md 9절 2항).** `bindListEditor` 가 47개 텍스트영역에 붙어 있다.
실제 키 입력으로 확인했다.

| 동작 | 입력 | 결과 |
|---|---|---|
| Enter 로 번호 잇기 | `3. 셋째` + Enter | `3. 셋째\n4. ` (1로 되돌아가지 않음) |
| Tab 으로 하위 시작 | `4. ` + Tab | `  1. ` (들여쓰고 번호 1부터 다시) |

3칸 필드(`goal`·`dplan`·`grat`)에는 일부러 붙이지 않았는데, `_join3` 이 줄바꿈을 공백으로
누르는 칸이라 목록이 의미가 없다. 올바른 판단이다.

**한글 IME 안전(CLAUDE.md 9절 13항).** Enter 를 읽는 13곳 전부에
`!e.isComposing && e.keyCode !== 229` 가 들어 있다. 빠진 곳이 없다.

**날짜 입력(CLAUDE.md 9절 12항).** 6block 은 네이티브 date 칸을 마스킹 텍스트 칸으로 감싸는
다른 방식을 쓴다(`wrapDateInput`·`dateMask`). 실제 입력으로 확인했다.

| 입력 | 화면 | 실제 값 |
|---|---|---|
| `26` | `26` | 빈 값 (0026 이 되지 않는다) |
| `999912` | `9999-12` | 빈 값 (덜 친 값은 서지 않는다) |
| `99991231` | `9999-12-31` | `9999-12-31` |
| `123456789012` | `1234-56-78` | 빈 값 (8자리로 끊어 5자리 연도가 구조적으로 불가능) |

연도가 항상 정확히 4자리가 되므로 항목의 의도는 다른 방식으로 충족된다. 그리고 여기서
통과하는 `9999-12-31` 은 이번에 고친 `MAX_YEAR` 가 서버에서 받는다.

**헤더 아이콘·제목 새로고침(CLAUDE.md 9절 14항).** `<a class="logo" id="logo-now"
title="오늘 탭 새로고침 · 지금 블록으로">` 가 아이콘과 제목을 함께 감싼다. 충족.

**서비스워커의 위험한 부분은 이미 제거돼 있다.** 프로젝트 메모리에 기록된
"navigate 폴백이 다른 페이지를 내줘 화면이 안 바뀐다"는 함정은 `sw.js` 에서 이미 빠졌고,
왜 뺐는지 주석에 상세히 남아 있다. 화면 요청은 그냥 통과한다.

### 판단을 남겨 두는 것 2가지 (고치지 않았다)

**(가) sw.js 가 정적 자원을 캐시한다.** CLAUDE.md 9절 16항은 "네트워크 pass-through,
**절대 캐시하지 않는다**(캐싱 워커는 고칠 때마다 옛 코드를 내준다)" 를 요구한다.
현재 `sw.js` 는 정적 자원을 네트워크 우선 + 캐시 폴백으로 두고, 폴백에서
`caches.match(req, { ignoreSearch: true })` 를 쓴다. 네트워크가 실패할 때만 캐시가 나오지만,
`ignoreSearch` 때문에 `app.js?v=새것` 요청이 `app.js?v=옛것` 캐시와 맞는다. 폰이 테일스케일로
붙어 화면이 깨어나는 순간 첫 요청이 실패하는 상황이 잦다고 기록돼 있어, 그때 옛 코드가
나올 수 있다. 오프라인 설치·빠른 로딩을 위한 의도적 선택으로 보여 손대지 않았다.
**규칙대로 pass-through 로 바꿀지 판단이 필요하다.**

**(나) manifest 아이콘에 192px 이 없다.** 현재 512x512, 180x180, any, maskable 이 있다.
CLAUDE.md 9절 1항은 192px 과 512px 을 요구한다. 180 은 apple-touch-icon 용이라
안드로이드 크롬 설치 아이콘 규격(192)과는 다르다. 영향이 작아 손대지 않았다.

### 검증하지 못한 것

**Cmd+Z 되돌리기(CLAUDE.md 9절 2항)를 확인하지 못했다.** 코드는 `document.execCommand
('insertText')` 대신 `.value` 를 직접 대입한다(app.js:3152·3166·3180·3185). 규정과 다른
방식이라 실행취소가 깨질 가능성이 있으나, **브라우저 자동화가 수식키를 전달하지 못해
확인에 실패했다.** 대조군(네이티브 타이핑 후 Cmd+Z)에서도 `z` 가 그대로 입력됐다.
확인하지 못했으므로 결함으로 보고하지 않는다. 손으로 한 번 눌러 보시면 바로 안다.

한 가지 더 밝혀 둔다. Enter 테스트가 처음에 실패해 목록 기능이 없다고 판단할 뻔했으나,
keydown 을 계측하니 자동화가 빈 키 이벤트(`key:""`, `keyCode:0`)를 보낸 것이었다.
키 이름을 고치니 정상 동작했다. 하네스 문제를 앱 결함으로 보고할 뻔한 사례다.

## 6. 여전히 못 본 범위

**"문제가 발견되지 않았다"와 "문제가 없다"는 다르다.** 아래는 이번에도 닿지 못한 곳이다.

| `multiprocessing` 프로세스 간 `init_db` 경쟁 | 자식 프로세스에서 conftest 격리가 풀려 실패. **launchd 이중기동 함정은 여전히 미확인** |
| WAL 파일(.db-wal/.db-shm) 실물 확인, 의도적 lock 후 재시도 | 미확인 |
| `_settings_cache` 무한 증가 시나리오 | 크기 제한이 없으나 설정 수가 고정이라 미확인 |
