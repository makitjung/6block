# 6block

하루를 30분 슬롯과 6개 코어 블록으로 나눠 **계획(PLAN) → 실행(DO) → 복기(SEE)** 하는 개인용 시간관리 대시보드입니다. Mac mini에서 상시 구동하고 Tailscale로 휴대폰에서 PWA(앱)처럼 사용합니다.

---

## 1. 만든 목적

- 하루를 **6개 코어 블록(B1~B6) + 2개 버퍼 블록**, 그 안의 **30분 슬롯**으로 쪼개 시간을 흘려보내지 않고 의식적으로 쓰기 위함.
- 블록마다 **무엇을 할지(PLAN)** 정하고, 슬롯마다 **실제로 한 것(DO)** 을 기록하고, 끝나면 **돌아보기(SEE)** 하는 Plan-Do-See 루프를 한 화면에서 돌리기 위함.
- 포모도로 집중, GTD 빠른 수집, 구글 캘린더·Things3 같은 외부 일정/할 일을 **한 화면에 통합**해 도구를 옮겨다니지 않기 위함.
- Mac mini(상시 가동)에 두고, 외부에서는 Tailscale 사설망으로만 접속해 어디서든 같은 데이터를 쓰기 위함.

---

## 2. 주요 특징

### 하루 8블록 구조

| 블록 | 구분 | 시간 |
|------|------|------|
| B1 | 코어 | 07:30 – 09:30 |
| B2 | 코어 | 09:30 – 11:30 |
| 점심 | 버퍼 | 11:30 – 12:30 |
| B3 | 코어 | 12:30 – 14:30 |
| B4 | 코어 | 14:30 – 16:30 |
| 저녁 | 버퍼 | 16:30 – 19:00 |
| B5 | 코어 | 19:00 – 21:00 |
| B6 | 코어 | 21:00 – 23:00 |

### 오늘 화면 (`/today`)

- **목표 3 · 달성 3 · 감사반성 3**, 메모·각오 입력.
- **오늘 컨셉 3칸**: 화면의 돌아보기 영역에서 그날을 끌고 갈 세 가지를 적어둡니다.
- 날짜 옆 괄호에 **그 요일의 컨셉**(설정에서 요일마다 지정).
- **빠른 수집함(GTD Inbox)**: 기본은 숨김이고 설정 `수집함 표시`로 켤 수 있습니다.
- **데스크톱 화면**: 현재 블록과 시간별 기록을 왼쪽에 두고, 구글 캘린더 일정·Things3 할 일·오늘 목표·주간 계획을 오른쪽에 모아 표시합니다. 일정과 할 일은 60초마다 갱신합니다.
- **블록마다 계획과 회고**를 나란히 적고, 블록 이름을 지정합니다. 블록 상단의 `일정`·`할 일`에서 해당 블록과 관련된 일정을 확인할 수 있습니다.
- **블록 바로가기**: 기본은 현재 블록을 보여 줍니다. `B1`~`B6` 등의 바로가기를 눌러 다른 블록으로 이동하고, `전체 블록 보기`로 하루를 펼칠 수 있습니다.
- **30분 슬롯**: 슬롯마다 구분, 할 일 입력, `한 일 기록`, 완료 체크가 있습니다.
- **자동저장**은 바꾼 칸만 보냅니다. 연결이 끊기거나 다른 탭에서 같은 칸을 수정했으면 상단의 저장 상태에서 보관된 입력을 확인할 수 있습니다.
- **내일로**를 누르면 내일 같은 블록에 복사할 계획과 덮어쓰는 칸을 먼저 보여 줍니다. 확인 후 내일 화면으로 이동하며, 이월한 블록에서 5분 동안 `이월 취소`를 사용할 수 있습니다.
- **하루 마감**: 상단의 `하루 마감`에서 하루 평가와 내일의 목표를 적고, 지나갔는데 기록이 빈 코어 슬롯을 채웁니다. `계획대로`를 누르면 한 일과 완료 체크가 함께 저장됩니다.
- **포모도로(슬롯 종료시각까지 집중)**: ▶를 누르면 그 30분 슬롯이 끝날 때까지 집중하고, 자동 모드는 슬롯이 시작되는 시각에 그 슬롯을 자동 시작합니다. 별도 휴식 단계는 없고 종료 시 종소리·알림으로 알립니다.

### 주간 화면 (`/week`)

- 주간 목표, **블록 테마(B1~B6 이름)**, 카테고리별 사용 시간 통계, 코어 블록 달성률.
- **이번 주 장기 항목**: 그 주에 걸친 장기 계획 막대가 **한 줄씩** 서고, 평소엔 장기 탭 이름을 그대로 씁니다. 줄의 `✎`를 누르면 그 주만의 문구를 따로 적을 수 있고(비우면 다시 장기 이름), 진척률을 바로 고치거나 `블록으로` 버튼으로 옮깁니다.
- **7일 격자에서 블록 이름을 바로 고칩니다.** 웹 화면 상단의 격자에서 날짜와 시간을 훑고, 각 블록의 시간 링크로 해당 날짜의 블록을 엽니다. 블록 이름을 비우면 `블록이름`에서 정한 주간 이름을 따릅니다. 지난 주 블록도 편집할 수 있습니다.
- 주간에서 정한 블록 이름이 일간 기본값이 되고, 일간에서 덮어쓸 수 있음.
- **템플릿은 다섯 종류입니다.** 세션시간 `S1`·`S2`…, 고정할일 `T1`…, 블록이름 `N1`…, 구분 `C1`…, 그리고 이 넷을 골라 묶는 주간 `W1`… 입니다. 다섯 종류 모두 별도명칭을 붙일 수 있어 `S1(기본)`·`W1(집중주)`처럼 나옵니다(주간이 고르는 칸에도 그대로 보입니다). 번호는 지운 자리를 다시 쓰지 않아 `S2 는 아침용`이라고 외워 둔 것이 어긋나지 않습니다. 만드는 곳은 **설정 탭의 시간·구조**이고, 고르는 곳은 주간 탭입니다.
- **주에 걸기**: `7일 보기` 머리의 고르는 칸에서 주간 템플릿(`W`)을 고르면 그 즉시 그 주에 적용됩니다. 묶어 둔 부분만 손대므로, 세션시간만 담은 주간 템플릿은 블록 이름과 구분을 건드리지 않습니다. 세션시간은 **그 주에만** 저장되어 다른 주와 설정값은 그대로 남고, 이미 적어 둔 것이 있는 날은 칸이 어긋나지 않게 건너뛰고 몇 날을 건너뛰었는지 알려 줍니다.
- **하루만 다르게**: 주를 건 뒤에도 날짜 머리의 `⋯` 를 누르면 그 날 하나에만 세션시간·고정할일·블록이름·구분을 따로 걸 수 있습니다. 걸어 둔 것이 있는 날은 `⋯` 에 표시가 남고, `안 걸기`를 고르면 떼어져 다시 주간(과 설정)을 따릅니다.
- **템플릿을 만드는 자리**(설정 · 시간·구조)는 화면 맨 위에 **펴진 채로** 섭니다. 한 줄을 눌러 펴고 `닫기`로 접으며, 오른쪽 위 빨간 `삭제`가 그 템플릿을 지웁니다. **추가해도 화면을 다시 받지 않아** 잇달아 여러 개를 만들 수 있고, 새로 만든 것은 주간이 고르는 칸에도 바로 나타납니다.
- 설정에 있던 **세션(블록) 시간 카드는 없앴습니다**(2026-09-04). 시간표는 세션시간 템플릿(`S`)으로 만들어 주간·하루에 겁니다.
- 구분은 시각이 아니라 **블록 안 순번**으로 잡습니다. `B1p4` 는 1블록의 네 번째 30분 칸이라, 세션시간을 바꿔도 자리가 어긋나지 않습니다. 블록 단위 42칸(요일 7 × 코어블록 6)과 칸 단위 168칸을 함께 쓸 수 있습니다.

### 장기 화면 (`/plan`)

- 연 · 분기 · 월 · 주 단위로 보는 **계획 막대** 하나로 관리합니다(표 없음). **기본은 주 단위**이고 이번 주가 왼쪽에서 두 번째 칸에 옵니다.
- 위쪽 `오늘 선`을 켜면 오늘 자리에 빨간 세로선과 `오늘` 깃발이 붙습니다(**기본은 꺼짐**). 진척률은 막대 안쪽을 같은 색 더 진하게 채워 보여 주고, 오른쪽 끝에 숫자로도 적습니다.
- **항목 접어 두기** · 편집칸의 `숨김`을 켜면 그 항목이 화면에서 빠집니다. 위쪽 `숨긴 항목 N개 보기`를 켜면 옅은 점선으로 다시 나오고, 거기서 `숨김`을 풀면 돌아옵니다.
- **왼쪽 줄은 코어블록 `B1`~`B6`**과 `미지정`이고, 위쪽 기간 열의 폭은 실제 날짜 수를 따릅니다.
- **한 항목을 여러 블록에 걸 수 있습니다.** 편집창에서 `B2` `B6`처럼 여러 개를 고르면 같은 막대가 그 줄마다 나오고, 어느 줄에서 끌어도 같이 움직입니다. 하나의 프로젝트를 두 블록에서 동시에 돌릴 때 씁니다.
- **연결선 두 가지** · 상위와 하위는 **하위 막대 한가운데에서 위로 올라가는 옅은 실선**으로, 한 항목이 여러 블록에 걸려 나뉜 것은 **막대 뒤에서 바깥으로 부푸는 희미한 점선 곡선**으로 이어집니다(점선은 최상위 항목만). **평소에는 그리지 않고, 막대에 손을 얹거나 편집칸을 열었을 때 그 묶음의 선만 켭니다** — 늘 그어 두면 화면 위아래를 가로지르는 줄이 수십 개가 되어 정작 막대가 안 보였습니다.
- **항목을 누르면 편집합니다.** 넓은 웹 화면에서는 오른쪽 편집 패널이 열립니다. 이름·진척률·블록·표시 상태는 자동저장됩니다. 기간은 시작일과 종료일을 입력한 뒤 `기간 적용`으로 두 날짜를 함께 저장합니다.
- **여러 블록에 걸린 항목은 한 곳에만 저장됩니다.** 어느 줄에서 이름·기간·진척률을 고치거나 끌어 옮겨도 나머지 줄에 그대로 함께 반영됩니다. 줄마다 따로 관리되지 않습니다.
- **색은 영역, 진하기는 계층 단계입니다** · 영역(프로젝트·투자·학습…)마다 색이 하나 있고, 그 색 안에서 **최상위 → 하위 → 하위2 세 단계**로 뚜렷하게 옅어집니다(더 깊은 하위는 마지막 단계로 그립니다). 영역 색은 `영역 관리`에서 팔레트 8종 중에 고릅니다.
- **한 줄 안에서는 영역 표시 순서대로** 위에서 아래로 놓입니다. 같은 영역 안에서만 칸을 나눠 쓰고, 영역이 바뀌면 그 아래로 내려가 섞이지 않습니다.
- **같은 영역에서 계획을 여럿 돌리면** 최상위 항목마다 색조를 조금씩 비틀어 서로 구분합니다. 한 항목의 하위들은 그 항목과 같은 색조를 씁니다.
- **한 줄 안에서 막대는 서로 가리지 않습니다.** 기간이 겹치면 아래 칸으로 내려 담고, **상위 항목이 자기 하위보다 항상 위 칸**에 옵니다. 블록마다 적어도 두 칸을 두고 **맨 아래 한 칸은 늘 비워** 둡니다(끌어다 놓는 자리).
- **한 계획과 그 하위는 붙어서 나옵니다.** 상위·하위 묶음이 연속한 칸을 통째로 쓰므로 사이에 남남인 항목이 끼어들지 않습니다. 하위가 없는 낱개 항목끼리는 기간이 안 겹치면 한 칸을 나눠 써 줄이 불필요하게 높아지지 않습니다.
- **블록은 항목마다 제 것만 봅니다.** 편집창에서 블록을 하나도 안 고르면 `미지정` 줄로 갑니다.
- **상위를 어느 블록에 놓으면 하위 사슬도 같이 따라갑니다**(손자까지). 실제로 블록이 바뀔 때만 내려보내므로, 그 뒤에 하위만 따로 다른 블록으로 빼 두면 상위의 이름·기간을 고쳐도 그대로 남습니다.
- **삭제를 확인할 때 함께 지워질 하위 항목 수를 알려 줍니다.** 삭제한 뒤 이 탭에서 `삭제 되돌리기`를 누르면 10분 내에 가장 최근 삭제 건을 복원할 수 있습니다. 하위 항목과 주별 계획도 함께 복원합니다. 상위 항목의 진척률은 숨긴 하위를 포함한 하위 평균입니다.
- **적어 넣은 기간은 하위가 있어도 그대로 남습니다.** 그리고 **상위 기간을 고쳐도 하위 기간은 건드리지 않습니다** — 끌어 옮기든 양 끝을 늘리든 편집창에 날짜를 적든 마찬가지입니다. 하위는 필요할 때 직접 옮깁니다(2026-09-04 사용자 요청).
- **막대 끌어 옮기기**: 좌우로 끌면 기간을 옮기고, 양 끝을 끌면 기간의 길이를 바꿉니다. 주·월 화면에서는 하루 단위로 움직입니다. 분기·연 화면에서는 시작일은 월요일, 종료일은 일요일에 맞춥니다. 끄는 동안 저장될 날짜가 표시됩니다.
- **세로 순서(↑↓)**: 같은 상위 아래 형제끼리 위아래를 바꿉니다(기간이 겹쳐 위아래 칸으로 나뉘어 선 하위들). 형제가 없으면 예전처럼 같은 영역 안에서 **계획 묶음째** 오르내립니다. 위아래로 끌어서도 됩니다.
- **하위계획으로 넣기**: 다른 막대 위로 끌어 잠시 멈추면 표시가 켜집니다. 놓은 뒤 확인하면 해당 막대의 하위가 됩니다.
- **상위에서 떼기**: 편집창의 `상위에서 떼기`로 최상위 항목으로 옮깁니다. 다른 영역을 선택하면 해당 영역의 최상위로 옮깁니다.
- **옮긴 막대는 사라지지 않습니다.** 끌어서 보이는 기간 밖으로 보내면 그 항목이 보이는 자리로 화면이 따라가고, 잠깐 깜빡여 어디로 갔는지 알려 줍니다.
- **지난 항목**(종료일이 오늘 이전)은 흐리게 해서 **기본으로 보여 줍니다.** 위쪽 `지난 항목 N개 숨기기`를 체크할 때만 화면에서 빠집니다.
- 하위 기간을 바꾸면 필요할 때 상위 기간을 넓혀 그 하위를 포함합니다. 하위 기간을 줄일 때 상위 기간은 그대로 유지합니다.
- **항목을 추가**하려면 상단 `+ 항목 추가`나 블록 옆 `+`를 누릅니다. `1주`·`1개월`·`1분기`·`1년`으로 기간을 고를 수 있습니다.
- 열 머리글로 다음 단위를 펼치고, 주 단위 열에서는 `↗`로 그 주의 주간 화면으로 갑니다.

### 그 외

- **PWA**는 홈 화면에 설치할 수 있습니다. 연결이 끊기면 열려 있는 화면의 자동저장 입력을 브라우저에 보관했다가 다시 보냅니다. 아이콘은 `scripts/make_icons.py`에서 생성하며 아이폰 홈 화면용 PNG(`apple-touch-icon.png`)도 제공합니다.
- **다크 / 라이트 테마** 토글.
- **날짜 칸**은 연월일을 이어 입력합니다(`20260914` → `2026-09-14`). 옆의 달력은 월요일부터 표시하고, `오늘`은 한국 날짜를 기준으로 합니다. 키보드에서 달력 버튼을 열면 방향키로 날짜를 옮기고 `Enter`로 고릅니다.
- **설정 · 서버 · 최근 오류**는 **이번에 서버가 뜬 뒤에 난 500 응답만** 셉니다. 고치고 재시작하면 0으로 돌아갑니다(로그를 이어 쓰기 때문에 예전에는 이미 고친 오류가 계속 빨갛게 남았습니다).
- **데이터**: 로컬 SQLite(`~/6block-data/blocks.db`), 매일 `.sql` 덤프 백업(로컬 + OneDrive 2곳). 같은 일별 작업이 5MB 넘게 불어난 서버 로그도 최근 1MB만 남기고 잘라 냅니다.
- **기술 스택**: Python 3.13 · FastAPI · Jinja2 · SQLite · 바닐라 JS(빌드 단계 없음).

## 3. 주의사항

- **Things3 연동은 macOS 전용**입니다. AppleScript로 Today 목록을 읽으므로 시스템 설정 > 개인정보 보호 및 보안 > 자동화에서 권한 허용이 필요합니다. Today 목록만 가져오며 시간 정보는 없습니다.
- **구글 캘린더**는 "설정 및 공유 > 캘린더 통합 > iCal 형식의 **비공개** 주소(.ics)"를 `.env`의 `GCAL_ICAL_URL`에 넣어야 동작합니다. 비워두면 캘린더만 비활성화되고 앱은 정상 작동합니다.
- **인증이 없습니다.** 서버는 `127.0.0.1:8000`에만 열리고, 밖에서는 **Tailscale serve가 HTTPS로만** 중계합니다(`https://<tailscale-호스트>` → `127.0.0.1:8000`). 같은 공유기의 다른 기기나 공개 인터넷에서는 포트에 직접 닿지 않습니다. 이 구성을 풀지 마세요.
- 쓰기 요청(POST)은 **Origin/Referer 검사**로 다른 사이트에서 오는 요청(CSRF)을 막습니다. 다른 도메인·리버스 프록시로 접속해 저장이 403이 되면 `.env`의 `SIXBLOCK_ALLOWED_ORIGINS`에 그 호스트를 넣으세요.
- 설정 탭의 `.env` 편집기는 값을 `********`로 **가려서** 보여줍니다. 그대로 저장하면 기존 값이 유지되고, 바꾸려면 자리표시를 지우고 새 값을 적으면 됩니다.
- 새 기기에 설치할 때는 `tailscale serve --bg 8000`을 먼저 실행해 HTTPS 중계를 만든 뒤 서비스를 올리세요. 설정은 tailscaled에 저장돼 재부팅 후에도 유지됩니다. 현재 상태는 `tailscale serve status`로 확인합니다.
- **시크릿은 커밋 금지.** `.env`, `*.db`, `*.key`, `*.crt`는 `.gitignore`로 제외되어 있습니다.
- **설치형 PWA는 설치 시점의 매니페스트(가로회전 등)를 앱에 구워 저장**합니다. `manifest.json`을 바꾸면(예: 세로 잠금 → 가로 허용) 휴대폰에서 **앱을 삭제하고 다시 설치**해야 반영됩니다.
- **캐시 동작**: 정적 파일·HTML은 `Cache-Control: no-cache` + `?v=<수정시각>` 캐시버스팅이 적용되어, 코드 변경은 새로고침으로 반영됩니다. 다만 이미 옛 버전을 캐시한 기기는 1~2회 새로고침(또는 PWA 재설치)이 필요할 수 있습니다.
- **서버 재시작 기준**: `app/static`·`app/templates`(JS/CSS/HTML) 변경은 자동 반영되지만, **`main.py` 등 파이썬 코드 변경은 서버 재시작이 필요**합니다(launchd가 `--reload` 없이 구동).
- 모든 시각은 **KST(Asia/Seoul)** 고정입니다.

## 4. 사용법

### 요구 환경

- macOS (Apple Silicon), Python 3.13, 프로젝트 가상환경(`.venv`).

### 설치

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # 이후 GCAL_ICAL_URL 입력(선택)
```

### 개발 실행

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
# 브라우저에서 http://127.0.0.1:8000  (자동으로 /today 로 이동)
```

### 상시 구동 (launchd)

Mac mini에서는 `~/Library/LaunchAgents/io.6block.uvicorn.plist`(`KeepAlive`)로 항상 떠 있습니다.

```bash
# 재시작 (코드 반영)
launchctl kickstart -k "gui/$(id -u)/io.6block.uvicorn"

# 등록 / 해제
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/io.6block.uvicorn.plist
launchctl bootout   "gui/$(id -u)/io.6block.uvicorn"

# 로그
tail -f ~/6block-data/uvicorn.err.log
```

### 휴대폰에서 앱으로 쓰기

1. 휴대폰을 Mac mini와 같은 Tailscale 네트워크에 연결.
2. 크롬으로 **`https://<tailscale-호스트>/today`** 에 접속(포트 없음, Tailscale serve가 중계). PWA 설치와 서비스워커는 HTTPS에서만 동작하므로 반드시 이 주소를 쓰세요.
3. 크롬 메뉴 → **홈 화면에 추가 / 앱 설치**로 PWA 설치.
4. 휴대폰 시스템의 **화면 자동 회전**이 켜져 있어야 가로 보기가 됩니다.

### 화면 / 점검 경로

- `/today` 오늘, `/week` 주간, `/plan` 장기(계획 막대), `/reflect` 고결감, `/analytics` 분석·검색, `/data` 데이터, `/settings` 설정.
- 고결감 작성칸의 **태그·다시 볼 날은 제목 행의 파란 `＋`** 뒤에 있습니다(2026-08-19). 어쩌다 쓰는 칸이 늘 한 행을 먹으면 내용칸이 그만큼 짧습니다. 붙여 두면 그 `＋` 에 개수와 날짜가 뜹니다(`＋ 2 · 10/01`). Record 고결감 탭도 같은 모양입니다 — 같은 일을 하는 칸이 프로그램마다 다르게 생기면 어느 쪽에서 뭘 할 수 있는지 외워야 합니다.
- `/api/health` 상태 한 벌(캘린더 읽기·쓰기 3종·Things3·AI·백업 최신·마지막 기록·최근 오류·코드 버전), `/api/now` 서버 KST 시각, `/version` 지금 서버가 내보내는 자산 버전.
- 같은 내용을 **설정 > 서버 > 상태** 카드에서 표로 봅니다. 초록은 정상, 빨강은 고장, 회색은 쓰지 않는 기능이라 로그를 뒤질 필요가 없습니다.

### 백업

```bash

.venv/bin/python scripts/backup.py
# 덤프 위치: ~/6block-data/backups/blocks-YYYYMMDD.sql
```

## 6. 테스트

코드를 고친 뒤에는 아래 두 가지를 모두 돌립니다.

```bash
# 1. pytest 전체 (1,818개, 약 42초). 먼저 pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q

# 2. 실제 HTTP 스모크 (242개). 추가 설치 없이 표준 라이브러리만 씁니다
.venv/bin/python tests/run_smoke.py
```

pytest 는 `tests/conftest.py` 가 임시 DB·임시 `.env` 로 갈아끼우고, 실제
`~/6block-data` 를 여는 순간 그 자리에서 실패시킵니다. 외부 연동(구글·Things3·AI)도
전부 꺼집니다. `pytest.ini` 가 starlette 의 구식 TemplateResponse 경고를 실패로 잡습니다.

스모크는 임시 폴더에 새 DB를 만들고 127.0.0.1:8011에 테스트 서버를 띄워 실제 HTTP 요청으로
242개 항목을 확인한 뒤, 서버를 내리고 임시 폴더를 지웁니다. **운영 DB(`~/6block-data/blocks.db`)와 8000 포트는
건드리지 않습니다.** 구글 캘린더·Things3 연동은 테스트에서 꺼집니다. 모두 통과하면 종료코드 0,
하나라도 실패하면 1을 돌려주므로 배포 전 확인이나 자동화에 그대로 쓸 수 있습니다.

확인하는 범위는 주요 화면 8개의 정상 응답, CSRF Origin 차단, 요일별 세션 시간(저장·검증·되돌리기),
하루 골격 생성의 멱등성, 필드 자동저장, 블록 시간 변경 시 장소 보존, 장기 계획 막대(추가·하위·자동 롤업·겹침·기간 이동·기간 조절·기간 4구분·하위지정·블록 배정·영역 색·삭제),
주간 연동(주간 목표로·블록으로), 오늘 컨셉 3칸, 수집함 표시 설정, 요일 컨셉,
아이콘(뿌리 PNG·ICO 응답), 정적 파일 캐시 헤더(`?v=` 유무), 상태판 `/api/health` 구성,
템플릿 다섯 종류(만들기·번호 매기기 · 주간이 묶은 부분만 적용 · 날짜별 따로 걸기·떼기 ·
격자 지연 렌더 · 세션시간 · 블록 이름 · 칸 단위 구분 B1p4), 하루 마감의 기록이 빈 슬롯 메우기입니다.

포트를 바꾸려면 `SIXBLOCK_TEST_PORT=8020 .venv/bin/python tests/run_smoke.py` 처럼 지정합니다.

## 7. 백업과 복원

매일 23시에 SQLite 스냅샷을 덤프로 만들고, 빈 데이터베이스에 복원해 무결성을 검사한 뒤 `~/6block-data/backups/blocks-YYYYMMDD.sql`과 OneDrive 또는 설정된 보조 폴더에 같은 파일을 저장합니다. 보관 기간은 30일입니다. 데이터 탭에서도 수동으로 백업을 만들고 대상별 상태를 확인할 수 있습니다.

복원할 날짜의 덤프를 별도 파일에서 먼저 검증합니다. 검사 결과가 `ok` 한 줄이면 서버를 내린 뒤 기존 DB와 WAL 관련 파일을 함께 보관하고 검증된 파일을 적용합니다.

```bash
backup_file="$HOME/6block-data/backups/blocks-20260725.sql"
restored_db=$(mktemp "$HOME/6block-data/blocks.restored.XXXXXX")
sqlite3 -bail "$restored_db" < "$backup_file"
sqlite3 "$restored_db" 'PRAGMA quick_check; PRAGMA foreign_key_check;'
```

```bash
launchctl bootout gui/$(id -u)/io.6block.uvicorn
previous_db=$(mktemp -d "$HOME/6block-data/before-restore.XXXXXX")
for file in blocks.db blocks.db-wal blocks.db-shm; do
    if test -f "$HOME/6block-data/$file"; then
        mv "$HOME/6block-data/$file" "$previous_db/"
    fi
done
mv "$restored_db" "$HOME/6block-data/blocks.db"
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/io.6block.uvicorn.plist
```

재시작한 뒤 화면과 최근 기록을 확인합니다. 복원 전 데이터는 `before-restore.*` 폴더에 보관됩니다.
