# 6block

하루를 30분 슬롯과 6개 코어 블록으로 나눠 **계획(PLAN) → 실행(DO) → 복기(SEE)** 하는 개인용 시간관리 대시보드입니다. Mac mini에서 상시 구동하고 Tailscale로 휴대폰에서 PWA(앱)처럼 사용합니다.

---

## 1. 만든 목적

- 하루를 **6개 코어 블록(B1~B6) + 2개 버퍼 블록**, 그 안의 **30분 슬롯**으로 쪼개 시간을 흘려보내지 않고 의식적으로 쓰기 위함.
- 블록마다 **무엇을 할지(PLAN)** 정하고, 슬롯마다 **실제로 한 것(DO)** 을 기록하고, 끝나면 **돌아보기(SEE)** 하는 Plan-Do-See 루프를 한 화면에서 돌리기 위함.
- 포모도로 집중, GTD 빠른 수집, 구글 캘린더·Things3 같은 외부 일정/할 일을 **한 화면에 통합**해 도구를 옮겨다니지 않기 위함.
- Mac mini(상시 가동)에 두고, 외부에서는 Tailscale 사설망으로만 접속해 어디서든 같은 데이터를 쓰기 위함.

---

## 2. 주요 특징

### 하루 8블록 구조

| 블록 | 구분 | 시간 |
|------|------|------|
| B1 | 코어 | 07:30 – 09:30 |
| B2 | 코어 | 09:30 – 11:30 |
| 점심 | 버퍼 | 11:30 – 12:30 |
| B3 | 코어 | 12:30 – 14:30 |
| B4 | 코어 | 14:30 – 16:30 |
| 저녁 | 버퍼 | 16:30 – 19:00 |
| B5 | 코어 | 19:00 – 21:00 |
| B6 | 코어 | 21:00 – 23:00 |

### 오늘 화면 (`/today`)

- **목표 3 · 달성 3 · 감사반성 3**, 메모·각오 입력.
- **오늘 컨셉 3칸**: 그날을 끌고 갈 세 가지를 1행 3열로 적어둡니다.
- 날짜 옆 괄호에 **그 요일의 컨셉**(설정에서 요일마다 지정).
- **빠른 수집함(GTD Inbox)**: 기본은 숨김이고 설정 `수집함 표시`로 켤 수 있습니다.
- **오늘 일정·할 일**: 구글 캘린더 일정과 Things3 Today 할 일을 최상단에 한 번에 모아 표시(60초 실시간 폴링).
- **블록마다 PLAN / SEE**를 한 행에 나란히 입력, 블록 이름 지정.
- **블록별 호버 버튼(일정 · 할 일)**: PLAN·SEE 위에서 그 시간대 캘린더 일정과 Things3 Today를 호버(폰은 탭)로 확인.
- **현재 블록만 보기**: 오늘 화면은 기본적으로 지금 시각의 블록만 표시하고, `전체 블록 보기` 버튼으로 8블록 전체를 펼쳐 스크롤.
- **30분 슬롯**: 슬롯마다 카테고리(색 띠), DO 입력, 실행 완료 체크박스.
- **포모도로(슬롯 종료시각까지 집중)**: ▶를 누르면 그 30분 슬롯이 끝날 때까지 집중하고, 자동 모드는 슬롯이 시작되는 시각에 그 슬롯을 자동 시작합니다. 별도 휴식 단계는 없고 종료 시 종소리·알림으로 알립니다.

### 주간 화면 (`/week`)

- 주간 목표, **블록 테마(B1~B6 이름)**, 카테고리별 사용 시간 통계, 코어 블록 달성률.
- **이번 주 장기 항목**: 그 주에 걸친 장기 계획 막대가 **한 줄씩** 서고, 평소엔 장기 탭 이름을 그대로 씁니다. 줄의 `✎`를 누르면 그 주만의 문구를 따로 적을 수 있고(비우면 다시 장기 이름), 진척률을 바로 고치거나 `블록으로` 버튼으로 옮깁니다.
- **7일 격자에서 블록 이름을 바로 고칩니다.** 칸 너비가 고정돼 이름이 길어도 격자가 늘어나지 않고 잘려 보이며, 눌러서 커서를 옮기면 나머지가 보입니다. 비우면 위 `이번 주 블록 이름` 카드의 주간 이름을 따릅니다. **지난 주 블록도 똑같이 고칠 수 있습니다.**
- 주간에서 정한 블록 이름이 일간 기본값이 되고, 일간에서 덮어쓸 수 있음.

### 장기 화면 (`/plan`)

- 연 · 분기 · 월 · 주 단위로 보는 **계획 막대** 하나로 관리합니다(표 없음). **기본은 주 단위**이고 이번 주가 왼쪽에서 두 번째 칸에 옵니다.
- 위쪽 `오늘 선`을 켜면 오늘 자리에 빨간 세로선과 `오늘` 깃발이 붙습니다(**기본은 꺼짐**). 진척률은 막대 안쪽을 같은 색 더 진하게 채워 보여 주고, 오른쪽 끝에 숫자로도 적습니다.
- **항목 접어 두기** · 편집칸의 `숨김`을 켜면 그 항목이 화면에서 빠집니다. 위쪽 `숨긴 항목 N개 보기`를 켜면 옅은 점선으로 다시 나오고, 거기서 `숨김`을 풀면 돌아옵니다.
- **왼쪽 줄은 코어블록 `B1`~`B6`**(+ 블록을 안 정한 항목이 모이는 `미지정` 한 줄)이고 **위쪽은 기간 열**입니다. 블록을 안 고르면 상위 항목의 블록을 따라갑니다.
- **한 항목을 여러 블록에 걸 수 있습니다.** 편집창에서 `B2` `B6`처럼 여러 개를 고르면 같은 막대가 그 줄마다 나오고, 어느 줄에서 끌어도 같이 움직입니다. 하나의 프로젝트를 두 블록에서 동시에 돌릴 때 씁니다.
- **연결선 두 가지** · 상위와 하위는 **하위 막대 한가운데에서 위로 올라가는 옅은 실선**으로 이어져 어느 계획에 딸린 것인지 보입니다. 한 항목이 여러 블록에 걸려 나뉜 것은 **막대 뒤(오른쪽 끝)에서 바깥으로 부푸는 희미한 점선 곡선**으로 이어집니다(최상위 항목만 긋습니다. 하위까지 다 그으면 화면이 복잡해집니다).
- **여러 블록에 걸린 항목은 한 곳에만 저장됩니다.** 어느 줄에서 이름·기간·진척률을 고치거나 끌어 옮겨도 나머지 줄에 그대로 함께 반영됩니다. 줄마다 따로 관리되지 않습니다.
- **색은 영역, 진하기는 계층 단계입니다** · 영역(프로젝트·투자·학습…)마다 색이 하나 있고, 그 색 안에서 **최상위 → 하위 → 하위2 세 단계**로 뚜렷하게 옅어집니다(더 깊은 하위는 마지막 단계로 그립니다). 영역 색은 `영역 관리`에서 팔레트 8종 중에 고릅니다.
- **한 줄 안에서는 영역 표시 순서대로** 위에서 아래로 놓입니다. 같은 영역 안에서만 칸을 나눠 쓰고, 영역이 바뀌면 그 아래로 내려가 섞이지 않습니다.
- **같은 영역에서 계획을 여럿 돌리면** 최상위 항목마다 색조를 조금씩 비틀어 서로 구분합니다. 한 항목의 하위들은 그 항목과 같은 색조를 씁니다.
- **한 줄 안에서 막대는 서로 가리지 않습니다.** 기간이 겹치면 아래 칸으로 내려 담고, **상위 항목이 자기 하위보다 항상 위 칸**에 옵니다. 블록마다 적어도 두 칸을 두고 **맨 아래 한 칸은 늘 비워** 둡니다(끌어다 놓는 자리).
- **한 계획과 그 하위는 붙어서 나옵니다.** 상위·하위 묶음이 연속한 칸을 통째로 쓰므로 사이에 남남인 항목이 끼어들지 않습니다. 하위가 없는 낱개 항목끼리는 기간이 안 겹치면 한 칸을 나눠 써 줄이 불필요하게 높아지지 않습니다.
- **블록은 항목마다 제 것만 봅니다.** 편집창에서 블록을 하나도 안 고르면 `미지정` 줄로 갑니다.
- **상위를 어느 블록에 놓으면 하위 사슬도 같이 따라갑니다**(손자까지). 실제로 블록이 바뀔 때만 내려보내므로, 그 뒤에 하위만 따로 다른 블록으로 빼 두면 상위의 이름·기간을 고쳐도 그대로 남습니다.
- 막대를 누르면 편집칸이 **두 줄**로 열립니다(첫 줄 이름·진척, 둘째 줄 기간·블록·영역). `저장`을 누르거나 **격자의 빈 곳 또는 입력칸 자체의 빈 자리를 누르면 닫힙니다.** 지우기는 막대 오른쪽 끝 `✕`, 상위로 넣기는 끌어다 붙이기로 합니다. 하위가 있는 항목의 진척률은 하위 평균입니다. 편집창에서 **영역을 바꾸면** 하위 항목은 상위에서 빠져 그 영역의 최상위가 됩니다.
- **적어 넣은 기간은 하위가 있어도 그대로 남습니다.** 대신 **상위가 움직인 만큼 하위도 따라 움직입니다** — 상위 시작일을 뒤로 밀면 하위 시작일도 그만큼 뒤로 가고, 종료일도 마찬가지입니다.
- **막대 끌어 옮기기**: 좌우로 끌면 **시작일이 가장 가까운 월요일에 붙고** 길이는 그대로입니다(끝을 끌 때는 **종료일이 일요일에** 붙습니다). 끄는 동안 막대가 그 자리로 움직이고 `7/20(월)~8/16(일)` 처럼 바뀔 날짜가 떠서, 보이는 자리가 그대로 저장됩니다. 요일이 어중간한 항목도 한 번 끌면 주에 맞춰집니다. 하위가 있으면 하위 사슬도 같은 날수만큼 함께 밀립니다. **양 끝 16px 안(마우스를 올리면 세로 손잡이가 보입니다)을 잡아 끌면** 그쪽 끝만 주 단위로 늘거나 줄어듭니다. **정확한 날짜는 막대를 눌러 편집창에 적습니다**(하루 단위로 그대로 저장됩니다).
- **하위계획으로 넣기**: 끌고 가서 **다른 막대 위에서 잠깐(0.35초) 멈추면** 양쪽에 표시가 켜지고, 그대로 놓으면 그 막대의 하위가 됩니다. 같은 줄이든 다른 줄이든 됩니다. 계속 움직이는 동안에는 잡히지 않으니 옆으로 미는 도중 엉뚱하게 붙지 않습니다. 편집창의 `상위 항목`으로 골라도 됩니다.
- **상위에서 떼기**: 하위 막대를 **같은 줄 안에서 곧장 아래(빈 칸)로 끌면** 상위에서 빠져 최상위 항목이 됩니다. 다른 블록 줄 **빈 자리**에 놓으면 상위는 그대로 두고 그 블록으로만 옮겨집니다.
- **옮긴 막대는 사라지지 않습니다.** 끌어서 보이는 기간 밖으로 보내면 그 항목이 보이는 자리로 화면이 따라가고, 잠깐 깜빡여 어디로 갔는지 알려 줍니다.
- **지난 항목**(종료일이 오늘 이전)은 흐리게 해서 **기본으로 보여 줍니다.** 위쪽 `지난 항목 N개 숨기기`를 체크할 때만 화면에서 빠집니다.
- **상위 기간도 직접 고칩니다.** 상위는 하위를 품도록 넓어지기만 하고 줄어들지 않으므로, 연 계획 안에 3개월짜리 하위 하나만 있어도 연 계획은 그대로 남습니다. 하위 밖으로 밀어내는 수정은 하위를 품는 선까지만 반영됩니다.
- **항목 추가창의 `1주` `1개월` `1분기` `1년` 버튼**으로 어느 화면 단위에서든 그 길이의 막대를 바로 만듭니다. 날짜는 그 뒤에 따로 고쳐도 됩니다.
- 열 머리글로 다음 단위를 펼치고, 주 단위 열에서는 `↗`로 그 주의 주간 화면으로 갑니다.

### 그 외

- **PWA**: 홈 화면에 설치, 오프라인 폴백, 서비스워커 캐시.
- **다크 / 라이트 테마** 토글.
- **데이터**: 로컬 SQLite(`~/6block-data/blocks.db`), 매일 `.sql` 덤프 백업(로컬 + OneDrive 2곳).
- **기술 스택**: Python 3.13 · FastAPI · Jinja2 · SQLite · 바닐라 JS(빌드 단계 없음).

## 3. 주의사항

- **Things3 연동은 macOS 전용**입니다. AppleScript로 Today 목록을 읽으므로 시스템 설정 > 개인정보 보호 및 보안 > 자동화에서 권한 허용이 필요합니다. Today 목록만 가져오며 시간 정보는 없습니다.
- **구글 캘린더**는 "설정 및 공유 > 캘린더 통합 > iCal 형식의 **비공개** 주소(.ics)"를 `.env`의 `GCAL_ICAL_URL`에 넣어야 동작합니다. 비워두면 캘린더만 비활성화되고 앱은 정상 작동합니다.
- **인증이 없습니다.** 서버는 `127.0.0.1:8000`에만 열리고, 밖에서는 **Tailscale serve가 HTTPS로만** 중계합니다(`https://<tailscale-호스트>` → `127.0.0.1:8000`). 같은 공유기의 다른 기기나 공개 인터넷에서는 포트에 직접 닿지 않습니다. 이 구성을 풀지 마세요.
- 쓰기 요청(POST)은 **Origin/Referer 검사**로 다른 사이트에서 오는 요청(CSRF)을 막습니다. 다른 도메인·리버스 프록시로 접속해 저장이 403이 되면 `.env`의 `SIXBLOCK_ALLOWED_ORIGINS`에 그 호스트를 넣으세요.
- 설정 탭의 `.env` 편집기는 값을 `********`로 **가려서** 보여줍니다. 그대로 저장하면 기존 값이 유지되고, 바꾸려면 자리표시를 지우고 새 값을 적으면 됩니다.
- 새 기기에 설치할 때는 `tailscale serve --bg 8000`을 먼저 실행해 HTTPS 중계를 만든 뒤 서비스를 올리세요. 설정은 tailscaled에 저장돼 재부팅 후에도 유지됩니다. 현재 상태는 `tailscale serve status`로 확인합니다.
- **시크릿은 커밋 금지.** `.env`, `*.db`, `*.key`, `*.crt`는 `.gitignore`로 제외되어 있습니다.
- **설치형 PWA는 설치 시점의 매니페스트(가로회전 등)를 앱에 구워 저장**합니다. `manifest.json`을 바꾸면(예: 세로 잠금 → 가로 허용) 휴대폰에서 **앱을 삭제하고 다시 설치**해야 반영됩니다.
- **캐시 동작**: 정적 파일·HTML은 `Cache-Control: no-cache` + `?v=<수정시각>` 캐시버스팅이 적용되어, 코드 변경은 새로고침으로 반영됩니다. 다만 이미 옛 버전을 캐시한 기기는 1~2회 새로고침(또는 PWA 재설치)이 필요할 수 있습니다.
- **서버 재시작 기준**: `app/static`·`app/templates`(JS/CSS/HTML) 변경은 자동 반영되지만, **`main.py` 등 파이썬 코드 변경은 서버 재시작이 필요**합니다(launchd가 `--reload` 없이 구동).
- 모든 시각은 **KST(Asia/Seoul)** 고정입니다.

## 4. 사용법

### 요구 환경

- macOS (Apple Silicon), Python 3.13, 프로젝트 가상환경(`.venv`).

### 설치

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # 이후 GCAL_ICAL_URL 입력(선택)
```

### 개발 실행

```bash
.venv/bin/uvicorn app.main:app --reload --port 8000
# 브라우저에서 http://127.0.0.1:8000  (자동으로 /today 로 이동)
```

### 상시 구동 (launchd)

Mac mini에서는 `~/Library/LaunchAgents/io.6block.uvicorn.plist`(`KeepAlive`)로 항상 떠 있습니다.

```bash
# 재시작 (코드 반영)
launchctl kickstart -k "gui/$(id -u)/io.6block.uvicorn"

# 등록 / 해제
launchctl bootstrap "gui/$(id -u)" ~/Library/LaunchAgents/io.6block.uvicorn.plist
launchctl bootout   "gui/$(id -u)/io.6block.uvicorn"

# 로그
tail -f ~/6block-data/uvicorn.err.log
```

### 휴대폰에서 앱으로 쓰기

1. 휴대폰을 Mac mini와 같은 Tailscale 네트워크에 연결.
2. 크롬으로 **`https://<tailscale-호스트>/today`** 에 접속(포트 없음, Tailscale serve가 중계). PWA 설치와 서비스워커는 HTTPS에서만 동작하므로 반드시 이 주소를 쓰세요.
3. 크롬 메뉴 → **홈 화면에 추가 / 앱 설치**로 PWA 설치.
4. 휴대폰 시스템의 **화면 자동 회전**이 켜져 있어야 가로 보기가 됩니다.

### 화면 / 점검 경로

- `/today` 오늘, `/week` 주간, `/plan` 장기(계획 막대), `/reflect` 고결감, `/analytics` 분석·검색, `/data` 데이터, `/settings` 설정.
- `/api/health` 연동 상태(구글 캘린더·Things3), `/api/now` 서버 KST 시각.

### 백업 / 복원

```bash
# 백업 (launchd io.6block.backup 로도 매일 자동 실행)
.venv/bin/python scripts/backup.py
# 덤프 위치: ~/6block-data/backups/blocks-YYYYMMDD.sql, 그리고 OneDrive/AI/6block-backups

# 복원
sqlite3 ~/6block-data/blocks.db < ~/6block-data/backups/blocks-YYYYMMDD.sql
```

## 6. 테스트

코드를 고친 뒤에는 아래 한 줄로 전체를 확인합니다. 추가 설치 없이 표준 라이브러리만 씁니다.

```bash
.venv/bin/python tests/run_smoke.py
```

임시 폴더에 새 DB를 만들고 127.0.0.1:8011에 테스트 서버를 띄워 실제 HTTP 요청으로 75개 항목을
확인한 뒤, 서버를 내리고 임시 폴더를 지웁니다. **운영 DB(`~/6block-data/blocks.db`)와 8000 포트는
건드리지 않습니다.** 구글 캘린더·Things3 연동은 테스트에서 꺼집니다. 모두 통과하면 종료코드 0,
하나라도 실패하면 1을 돌려주므로 배포 전 확인이나 자동화에 그대로 쓸 수 있습니다.

확인하는 범위는 주요 화면 8개의 정상 응답, CSRF Origin 차단, 요일별 세션 시간(저장·검증·되돌리기),
하루 골격 생성의 멱등성, 필드 자동저장, 블록 시간 변경 시 장소 보존, 장기 계획 막대(추가·하위·자동 롤업·겹침·기간 이동·기간 조절·기간 4구분·하위지정·블록 배정·영역 색·삭제),
주간 연동(주간 목표로·블록으로), 오늘 컨셉 3칸, 수집함 표시 설정, 요일 컨셉입니다.

포트를 바꾸려면 `SIXBLOCK_TEST_PORT=8020 .venv/bin/python tests/run_smoke.py` 처럼 지정합니다.

## 7. 백업과 복원

매일 23시에 `~/6block-data/backups/blocks-YYYYMMDD.sql` 덤프가 생기고 OneDrive에도 같은 파일이 복사됩니다(30일 보관). 설정 화면의 데이터 탭에서 즉시 덤프를 만들 수도 있습니다.

복원은 아래 순서로 합니다. 먼저 서버를 내려야 WAL이 섞이지 않습니다.

```bash
launchctl bootout gui/$(id -u)/io.6block.uvicorn
mv ~/6block-data/blocks.db ~/6block-data/blocks.db.old
sqlite3 ~/6block-data/blocks.db < ~/6block-data/backups/blocks-20260725.sql
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/io.6block.uvicorn.plist
```

복원 뒤 화면이 정상인지 확인한 다음 `blocks.db.old`를 지우세요. 덤프 파일명을 복원하려는 날짜로 바꿔서 실행합니다.
